# 地籍調査日報アプリ

## アプリの目的

Googleフォームで運用していた「地籍調査日報」を置き換えるWebアプリです。
作業者が自分で入力履歴を確認・修正でき、管理者は月別・工程別の集計を自動で行えます。

## 解決できる課題

| 課題 | 解決方法 |
|------|----------|
| 入力内容を管理者しか見られない | 作業者本人が自分の履歴を確認できる |
| 過去の入力を確認できない | 「自分の履歴」画面で一覧表示 |
| 間違えた場合に修正できない | 「編集・削除」画面で修正可能 |
| 毎回名前を選ぶのが面倒 | セッション内は名前を自動保持 |
| 重複入力による二重計上リスク | 時間帯重複を自動検出して警告 |
| 月末の手作業集計が必要 | 管理者画面で自動集計・Excel出力 |

## インストール方法

### 前提条件
- Python 3.10 以上がインストールされていること

### 手順

```bash
# 1. アプリフォルダに移動
cd work_report_app

# 2. 仮想環境を作成（推奨）
python -m venv venv
venv\Scripts\activate   # Windows

# 3. 依存パッケージをインストール
pip install -r requirements.txt
```

## 起動方法

```bash
cd work_report_app
streamlit run app.py
```

ブラウザが自動的に `http://localhost:8501` で開きます。

## 使い方

### 1. 利用者選択

- アプリ起動後、作業者名を選択して「この名前でログイン」をクリック
- 同じセッション内では2回目以降は名前選択が不要です

### 2. 日報入力

- サイドバーの「日報入力」をクリック
- 作業日・班・工程ID・開始時刻・終了時刻・作業場所を入力
- 終了時刻が開始時刻より前の場合は、翌日終了として作業時間を計算
- 作業時間は小数ではなく「4時間15分」のように表示
- 「日報を保存する」をクリックで保存
- 時間帯が重複している場合は警告が表示されます

### 3. 自分の履歴確認

- サイドバーの「自分の履歴」をクリック
- 月・班・工程ID・作業場所でフィルタリング可能

### 4. 編集・削除

- サイドバーの「編集・削除」をクリック
- 自分の日報のみ選択・編集・削除できます
- 削除は確認メッセージが表示されてから実行されます

## 管理者画面の見方

**「石野」でログインした場合のみ**、サイドバーに「管理者画面」が表示されます。

### 集計タブ

| タブ | 内容 |
|------|------|
| A. 月別・作業者別 | 各作業者の月別合計作業時間 |
| B. 月別・作業者別・工程別 | 工程IDごとの合計時間 |
| C. E工程 出勤日数 | E工程の出勤日数（同日複数入力=1日） |
| D. FR工程 作業時間 | FR工程の合計作業時間 |
| E. 工程ID別 | 工程IDごとの月別合計時間 |

### フィルター

月・作業者・班・工程ID・作業場所でフィルタリングして一覧を絞り込めます。

---

## E工程とFR工程の集計ルール

### E工程（工程IDがEで始まるもの）

交通費計算のため、**出勤日数**を重視します。

- 同じ作業者が同じ日に複数のE工程を入力しても、**出勤日数は1日**としてカウント
- 管理者画面タブCで確認できます

### FR工程（工程IDがFRで始まるもの）

**作業時間**を重視します。

- 作業者別・工程ID別・月別に合計時間を集計
- 管理者画面タブDで確認できます

---

## 重複入力警告の仕様

以下の条件を満たす場合、保存前に警告を表示します：

- **同じ作業者**が
- **同じ作業日**に
- **時間帯が重なる**入力をしようとした場合

重複の検出は完全一致だけでなく、**時間帯の部分的な重なり**も検出します。

例：
- 既存入力：9:00〜12:00
- 新規入力：10:00〜11:00
→ 「時間帯が重複しています」と警告

日付またぎの入力にも対応しています。
例：22:00〜00:00 → 2時間として表示されます。

警告後に「保存しない」または「それでも保存する」を選択できます。

## SQLiteデータベースの保存場所

```
work_report_app/
  data/
    work_report.db   ← ここに保存されます
```

初回起動時に自動的に作成されます。

### テーブル構造（work_reports）

| カラム | 型 | 説明 |
|--------|-----|------|
| id | INTEGER | 自動採番 |
| work_date | TEXT | 作業日（YYYY-MM-DD） |
| worker_name | TEXT | 作業者名 |
| team | TEXT | 班 |
| process_id | TEXT | 工程ID |
| process_name | TEXT | 工程名 |
| process_type | TEXT | E / FR / OTHER |
| start_time | TEXT | 開始時刻（HH:MM） |
| end_time | TEXT | 終了時刻（HH:MM） |
| hours | REAL | 作業時間（時間数） |
| work_place | TEXT | 作業場所 |
| note | TEXT | 備考 |
| created_at | TEXT | 登録日時 |
| updated_at | TEXT | 更新日時 |
| deleted | INTEGER | 0=有効、1=論理削除 |

## バックアップ方法

`data/work_report.db` ファイルをコピーするだけでバックアップできます。

```bash
# 例：日付付きでバックアップ
copy data\work_report.db data\work_report_backup_20250513.db
```

定期的（週1回など）にバックアップすることを推奨します。

## 実運用時の注意点

> **⚠️ 認証について**
>
> 現在は作業者名の選択のみで管理者判定を行っています。
> 本番運用では、**パスワード認証やGoogleログイン（OAuth）などの認証機能を追加**することを強く推奨します。
> 名前を変えるだけで管理者画面にアクセスできてしまうため、セキュリティリスクがあります。

> **⚠️ データベースについて**
>
> SQLiteは簡易的なローカル運用向けです。
> 複数人が同時に本格利用する場合は、**PostgreSQLやSupabaseなどのサーバー型DBへの移行**を検討してください。

> **⚠️ 個人情報の管理**
>
> 作業者名・作業内容などの個人情報が含まれるため、**`data/work_report.db` の管理に注意**してください。
> 不要なユーザーへの共有・公開は避けてください。

> **⚠️ バックアップ**
>
> `data/work_report.db` を定期的にバックアップしてください。
> PCが壊れた場合やファイルが破損した場合に備え、外部ストレージやクラウドへの保存を推奨します。
